> **概要：** 決定論的シグナルが利用できない場合に、AppsFlyer が確率論的アトリビューションを適用できるよう、広告エンゲージメントデータをどのように設定するかを解説します。

<div id="about-probabilistic-modeling" />

## 確率論的モデリングによるアトリビューションについて

IDFA、GAID、リファラーデータなどの決定論的識別子が、プラットフォームの制限やユーザーのプライバシー設定によって利用できない場合、AppsFlyer は確率論的モデリングを用いてインストールやリエンゲージメントをアトリビューションします。

この手法では、利用可能なデバイス情報やコンテキストシグナルを評価し、コンバージョン元として最も可能性の高いソースを選定します。これにより、直接的な識別子が存在しない場合でも、合理的に高い確度でアトリビューションできるケースでは、計測の継続性を維持し、ネットワークに適切なクレジットを付与できます。

確率論的アトリビューションの精度は、利用可能なシグナルの品質に依存します。ネットワークから提供されるデータの強度や完全性は、アトリビューションの優先順位および成功率に直接影響します。データの質が高いほど、複数の候補が存在する場合に、最終的な勝者として選ばれる可能性が高まります。

<div id="when-is-probabilistic-modeling-used" />

### 確率論的モデリングはいつ使用されますか？

AppsFlyer は、決定論的データが利用できない場合に、以下のようなケースで自動的に確率論的モデリングを適用します。

* iOS の SKAN フロー（SKAN 経由のインストール後）
* Web-to-app のコンバージョン
* クロスデバイスの計測（例：デスクトップ広告接触後のモバイルインストール）
* 計測アクセスが制限されているデバイスや環境
* 決定論的アトリビューションが不可能な CTV、PC、コンソールの計測

### 確率論的モデリングのフローとは

確率論的モデリングは、以下のステップで構成されます。

1. ユーザーがパートナーネットワーク上の広告に接触します（クリックまたはインプレッション）。
2. パートナーが、関連するデバイスおよびコンテキストシグナルを含む AppsFlyer のアトリビューションリンク、または HTTP ヘッダーを送信します。
3. アプリ起動時に決定論的なマッチが見つからない場合：
   * AppsFlyer が広告接触時およびアプリ起動時のコンテキストを評価します。
   * シグナルが確率論的条件を満たしている場合、その広告接触は有効なアトリビューション候補となります。
4. AppsFlyer のアトリビューションロジックが、最も直近かつ優先度の高いマッチを選択します。

> 📘 **注**
>
> 確率論的モデリングは、決定論的手法を上書きするものではありません。あくまで、決定論的手法が機能しない場合にのみ適用されます。

## 確率論的モデリングのためのエンゲージメントデータ設定

確率論的モデリングをサポートするには、以下が必要です：

* 必要なパラメータを含むアトリビューションリンク、または HTTP ヘッダーを実装する
* 標準の <Anchor target="_blank" href="/marketers/ja/docs/about-link-structure-and-parameters?utm_source=chatgpt.com">AppsFlyer リンク構造</Anchor>に従う

### 必須パラメータ

AppsFlyer は、確率論的アトリビューションのために以下のシグナルを使用します。

| パラメータ | 説明 | iOSの例： | Androidの例： |
| --- | --- | --- | --- |
| `af_ip` | 広告接触時のユーザーの IP アドレス | `192.168.0.12` | `192.0.2.45` |
| `af_model` | デバイスモデル識別子 | `iPhone14,1` | `SM-G991B` |
| `af_os_version` | OS の完全なバージョン | `17.5.0` | `13` |
| `af_language` | ユーザー端末の言語設定 | `en-US` | `he-IL` |
| `af_ua` | ユーザーエージェント文字列（ブラウザまたは WebView） | `Mozilla/5.0 (iPhone; CPU iPhone OS 17_5_1 like Mac OS X)...` | `Mozilla/5.0 (Linux; Android 13; SM-G991B)...` |

> 📘 **注**
>
> アトリビューションリンクにパラメータが含まれていない場合でも、可能な限り AppsFlyer は HTTP ヘッダーから情報を抽出します。

### ベストプラクティス

* 標準のリンク構造を使用してください。すべてのパラメータは、クエリ文字列または HTTP ヘッダー経由で渡す必要があります。
* ネットワークから提供されるシグナルの強度と完全性は、アトリビューションの優先順位および成功率に直接影響します。データの質が高いほど、複数候補が存在する場合に勝者として選ばれる可能性が高まります。
* シグナルの強度を重視してください。複数の候補がある場合、より強く、かつ直近のシグナルが優先されます。
