## Data Locker для партнёров

Data Locker для партнеров доставляет данные приложения в облачное хранилище. Рекламодатели задают разрешения, на основе которых AppsFlyer может предоставлять выбранные данные определенному партнеру.

<div id="data-locker-features" />

<Accordion title="Возможности Data Locker">

| Функциональность | Описание |
| --- | --- |
| Варианты хранилища (облако) | Ваше хранилище (корзина) в:<ul><li>AWS</li><li>GCS</li><li>Яндекс</li><li>BigQuery</li></ul><Anchor target="_blank" href="/marketers/ru/docs/data-locker-for-marketers#storage-options">О вариантах хранилищ</Anchor> |
| Поддержка нескольких приложений | Поддерживает данные приложений, интегрированных с вами. Чтобы вы могли получать эти данные, рекламодатель должен предоставить разрешение по каждому отчету. |
| Форматы данных | <ul><li>Для облачной корзины:<ul><li>CSV</li><li>Parquet</li><li>Adobe</li></ul></li><li>Локальное хранилище данных</li></ul> |
| Обновление данных | Частота обновления данных зависит от типа отчета:<ul><li>**Каждый час:** данные генерируются непрерывно</li><li>Ежедневно: некоторые отчеты формируются ежедневно и доступны на следующий день</li></ul> |

## Архитектура хранилища данных

<div id="overview" />

<Accordion title="Обзор">

Данные записываются в выбранный вами тип хранилища. Перейти с одного варианта на другой можно в любой момент. Изменение вступает в силу в течение нескольких часов.

Данные в облачной корзине организованы с помощью иерархической структуры папок по типам отчетов, дате и времени. Ниже представлен пример такой структуры.

![DLFolderOVerview.png](https://files.readme.io/78f360ec1df72253e5b2cd725f3eecf4e17548a7f06b544a94a75a2c319d77a0-18107910420369.png)

Данные конкретного отчета содержатся в папках по часам (h), связанных с этим отчетом.

* Количество часовых папок зависит от того, как часто поступает отчет (раз в час или ежедневно).
* Данные предоставляются в сжатых файлах Snappy или GZIP, или в виде несжатых файлов в формате Parquet или CSV.
* Файлы с данными состоят из столбцов (полей).
* Структура столбцов определяется для каждого типа отчета.

</Accordion>

<Accordion title="Структура папок">

| Папка | Описание |
| --- | --- |
| data-locker-hourly | ![DLHourly.png](https://files.readme.io/c257b82d22622d97808a6c23603ac4eee9f2ab091bcb68a33637ac4fb749fdff-18107874510353.png)<ul><li>Название папки верхнего уровня в корзине зависит от облачного сервиса.</li><li>Папка *data-locker-hourly* содержит темы отчетов.</li></ul>**Примеры структуры папок в зависимости от владельца корзины и облачного сервиса**:<ul><li>**Ваша корзина в AWS**: *&lt;af-datalocker-префикс вашей корзины>/&lt;generated-home-folder>&lt;subscription-id>*</li><li>**Ваша корзина в GCS:** &lt;название вашей корзины>/&lt;generated-home-folder>/&lt;subscription-id></li></ul> |
| t (тема) | Тип отчета связан с предметом отчета. |
| dt (дата) | Это дата, связанная с данными. В большинстве случаев это дата, когда произошло событие. |
| h (час) | Папки h соответствуют времени поступления данных в AppsFlyer. Например, события установки, полученные с 14:00 по 15:00 UTC, передаются в папку h=14. Примечание! Между моментом поступления данных в AppsFlyer и передачей папки h в Data Locker существует задержка около 6 часов. Таким образом, папка h=14 передается через шесть часов, в 23:00 UTC.<br /><br />**Характеристики папок**:<ul><li>Часовых папок h всего 24. Они пронумерованы от 0 до 23. Например, h=0, h=1 и так далее.</li><li>Кроме того, папка late содержит события за предыдущий день, которые поступили после полуночи (другими словами, события, которые поступили с 00:00 до 02:00 UTC следующего дня). Например, пользователь устанавливает приложение в понедельник в 08:00, событие поступает во вторник в 01:00. Событие записывается в папку late понедельника.</li><li>Данные, поступающие после 02:00, записываются в папку, соответствующую фактическим дате и времени получения.</li><li>Обязательно используйте данные из папки late. Они не дублируются в других папках.</li><li>\_temporary folder: В некоторых случаях мы создаем в папке h временную папку. Не обращайте на временные папки и подпапки внимания. Например: /t=impressions/dt=2021-04-11/h=18/**\_temporary**.</li></ul> |
| Объединенные данные | Данные по всем приложениям предоставляются в объединенных файлах. При загрузке данных, чтобы определить, к какому приложению относятся те или иные данные, используйте поле app\_id.<br /><br />**Пример файлов с данными в папке h=2**<br /><br />![UnifiedByApp.png](https://files.readme.io/dbc39c2ce99c1ff607fd553b9c9034e55728c102f31fd18a501cc00910267b28-18107874522513.png)<ul><li>Убедитесь, что процесс загрузки данных настроен так, что:<ul><li>Пользоваться данными можно только после получения флага \_SUCCESS.</li><li>Загружаются все файлы с *расширением .gz.*</li></ul></li></ul> |
| Флаг завершения | Флаг последнего файла (завершения) устанавливается, когда записаны все данные для определенной папки h.<ul><li>Не просматривайте данные в папке, пока не убедитесь, что у нее есть флаг \_SUCCESS.</li><li>Флаг \_SUCCESS устанавливается, даже когда данные для записи в конкретную папку отсутствуют, т. е. эта папка пуста. т. е. эта папка пуста.</li></ul> |
| Сжатие | Файлы сжимаются с помощью gz. После распаковки архива:<ul><li>У файлов нет расширения.</li><li>Каждый файл имеет строку заголовка, содержащую названия столбцов (полей).</li></ul> |
| Последовательность столбцов | Последовательность полей в отчетах всегда одинакова. Новые поля добавляются справа от существующих.<br /><br />Определения столбцов (полей) задаются для каждого отчета. Описание см. в статье по соответствующему отчету. |
| Рекомендации по заполнению полей | **Пустые или незаполненные поля**: Некоторые поля пусты или имеют значение *null*. Это говорит об отсутствии данных для предоставления в контексте этого отчета. Как правило, *null* означает, что соответствующее поле не заполняется в контексте отчета и типа приложения. Пустое значение "" означает, что поле актуально в этом контексте, но данные для его заполнения не найдены.<br /><br />**Часовой пояс и валюта**:<br /><br />Настройки часового пояса и валюты конкретного приложения игнорируются для данных, предоставляемых Data Locker. Таким образом:<ul><li>**Часовой пояс**: даты и часы указаны по поясу UTC.</li><li>**Валюта**: значения в поле event\_revenue\_usd указаны в долларах США.</li></ul>**Значения с запятыми**: Эти запятые содержатся в двойных кавычках `"`, например, `` `"iPhone6,1"` ``. |

<Accordion title="Варианты хранилища">

* Вы выбираете, кому принадлежит хранилище, в которое будут записываться данные: AWS, GCS и BigQuery.
* Изменить выбор хранилища можно в любое время.

  * Мы начнем записывать данные в новое хранилище в течение часа.
  * Мы продолжим записывать данные в прежнее хранилище в течение переходного периода в 7 дней. Время истечения переходного периода отображается в пользовательском интерфейсе. Используйте переходный период, чтобы обновить процессы загрузки данных.
  * **Изменение корзин**: если вы меняете хранилище, данные отправляются в обе корзины в течение переходного периода продолжительностью 7 дней, что позволяет согласовать процесс потребления данных.

<div id="notice-to-security-officers" />

#### **Примечание для сотрудников службы безопасности**

Рассмотрим:

* Корзина или хранилище предназначены только для использования AppsFlyer. Никакой другой субъект не должен записывать данные в этот вариант хранения.
* Вы можете удалить данные в корзине через 25 часов после того, как мы их запишем.
* Данные, которые мы записываем в хранилище, являются копией данных, уже находящихся на наших серверах. Данные продолжают находиться на наших серверах в соответствии с нашей политикой хранения данных.
* По техническим причинам нам иногда необходимо удалять и переписывать данные. По этой причине нам требуются  разрешения на удаление и списки. Ни разрешения на удаление, ни на списки не несут для вашей безопасности никакой угрозы. В отношении списков мы являемся единственным субъектом, осуществляющим записи в корзине. Что касается удаления, мы можем восстановить данные.

</Accordion>

<div id="multipleconnection-principles-more-than-one-destination" />

<Accordion title="Принципы множественных подключений (более одного пункта назначения)">

В Data Locker вы можете отправить некоторые или все ваши данные в разные хранилища (определенные в настройках подключения). Например, вы можете отправить данные приложения A в AWS, а данные приложения B — в GCS.

Каждое подключение состоит из полного набора настроек Data Locker, включая пункт назначения. Настройки подключений не зависят друг от друга.

При управлении подключениями учитывайте следующее:

* В настройках Data Locker подключения отображаются на вкладках. Каждое подключение имеет собственную вкладку настроек, на которой можно управлять подключением. По умолчанию открывается вкладка Data Locker.
* Чтобы создать новое подключение:
  1. Нажмите **Добавить подключение**.
  2. Задайте имя для подключения и выберите тип хранилища.
  3. Нажмите **Сохранить**.  
     После сохранения подключение отображается рядом с вкладкой Data Locker. Значок каждой вкладки представляет тип хранилища.
* Чтобы просмотреть сведения о подключении, дублировать или удалить подключение, нажмите ⋮ (опции).

</Accordion>

Выполните одну или несколько из следующих процедур настройки хранилища:
