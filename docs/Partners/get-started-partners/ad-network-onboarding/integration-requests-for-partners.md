> 📘 **Important!**
>
> Changes to AppsFlyer postbacks and attribution URL structures affect all existing and future campaigns across all apps.

Some integrations are fully automated and can be managed directly through the [Self-serve integration management platform for ad networks](/docs/self-serve-integration-management-for-ad-networks), enabling greater efficiency and faster implementation.

For integrations that are not yet automated, requests to change your settings must be submitted via the [partner assistant widget](https://files.readme.io/addb1c20a1a76a7726cc88fb87764c3884d0c09d9190ed36a4971beceb7a5cf1-33715331288593.gif). **To submit a request:**

1. From the top right of any AppsFlyer page, click the Help icon.
2. Select the following sequence of options in the widget:  
   **Contact our team** > **(2) I would like to understand or update my integration** > **(1) Update my integration**.
3. Select either **Advanced privacy or SKAD mode** or **Default mode**.
4. Provide the necessary requirements as specified in the following table:

| Request | Details | Requirements |
| --- | --- | --- |
| <span id="enable-rejected-postback"></span>Enable rejected postback | Allow sending postbacks of rejected installs and in-app events due to fraud or non-compliance with validation rules. | **To enable:**<ol><li>Follow the instructions in [Self-serve integration management for ad networks](/docs/self-serve-integration-management-for-ad-networks) to configure the rejected postback in the AppsFlyer dashboard.</li><li>Make sure to append the rejected parameters below to your default postback template (install/in-app event)<ul><li>`{is-rejected}</li><li>{blocked-reason}</li><li>{blocked-sub-reason}</li><li>{blocked-reason-value}</li></ul></li><li>Once any of the rejected parameters are added to both the Default postbacks, the rejected install/in-app event postbacks are enabled.</li></ol>In case of any issues, or if you can't access to Postback Management Platform:<ol><li>Select **Default mode** from the widget.</li><li>Write "Enable rejected postback" as the ticket title.</li><li>Share the following information:<ul><li>Your PID or login username</li><li>[Recommended] The names of the receiving parameters (defined by your technical team) for the macros is-rejected},{blocked-reason},{blocked-sub-reason},{blocked-reason-value}`</li><li>To which type of postback (install, in-app event, or both) the parameters should be added</li></ul></li></ol> |
| <span id="enable-retargeting"></span>Enable retargeting | Allow retargeting activity measurement.<br />AppsFlyer provides the following macros in the postback to identify if the campaign is a retargeting campaign and the conversion type (re-attribution or re-engagement):<ul><li>`is-retarget`</li><li>`retargeting_conversion_type`</li></ul>[More about retargeting.](/marketers/docs/retargeting-attribution-guide) | **To enable:**<ol><li>Follow the instructions in [Self-serve integration management for ad networks](/docs/self-serve-integration-management-for-ad-networks) to configure the postback in the AppsFlyer dashboard (install/in-app event)</li><li>Once the below parameters are added and the configuration is saved, the 'enable retargeting' toggle on the AppsFlyer backend will be automatically enabled.<ul><li>`{is-retarget}</li><li>{retargeting-conversion-type}`</li></ul></li></ol>In case of any issues, or if you can't access to Postback Management Platform:<ol><li>Select **Default mode** from the widget.</li><li>Write "Enable Retargeting"as the ticket title.</li><li>Share the following information:<ul><li>Your PID or login username</li><li>[Recommended] The names of the receiving parameters (defined by your technical team) for the macros `is-retarget` and `retargeting_conversion_type`.</li><li>To which type of postback (install, in-app event, or both) the parameters should be added</li><li>Indicate if a re-engagement postback is required for re-engagement events (meaning the first app-open of an existing app after clicking on a retargeting campaign ad)</li></ul></li></ol> |
| <span id="enable-uninstall"></span>Enable uninstall | Get postbacks of `af_uninstall` in-app events to measure uninstalls. | **To enable:**<ol><li>Select **Default mode** from the widget.</li><li>Write "Enable af\_uninstall in-app event postback" as the ticket title.</li><li>Share your PID or login username</li></ol> |
| <span id="enable-sending-session-data"></span>Enable sending session data | Allow data sharing for `af_app_opened` in-app event.<br /><br />[More about session data.](/marketers/docs/measure-sessions) | **To enable:**<ol><li>Select **Default mode** from the widget.</li><li>Write "Enable af\_app\_opened postback" as the ticket title.</li><li>Share your PID or login username.</li></ol> |
| <span id="enable-postbacks-retry"></span>Enable postbacks retry | Enable sending a postback several times in case of a sending failure.  <br />Use `postback-id` macro to identify the postback ID.<br /><br />[More about postback retries.](/docs/postback-retries) | **To enable:**<ol><li>Select **Default mode** from the widget.</li><li>Write "Enable Postbacks Retry" as the ticket title.</li><li>Share the following information:<ul><li>Your PID or login username</li><li>The receiving parameter name for the `postback-id` macro</li></ul></li></ol> |
| <span id="update-postback"></span>Update postback | Change the current postback structure (for example, delete/add parameters, change endpoint URL.)<br /><br />[More about postbacks and macros.](/docs/postback-macros-for-ad-networks) | Follow the instructions in [Self-serve integration management for ad networks](/docs/self-serve-integration-management-for-ad-networks) to configure the the postback in the AppsFlyer dashboard (install/in-app event)<br /><br />In case of any issues, or if you can't access the Postback Management Platform:<ol><li>Select Default mode from the widget.</li><li>Write "Update postback" as the ticket title.</li><li>Share the following information:</li></ol><ul><li>Your PID or login username</li><li>The new postback structure, based on available macros</li></ul> |
| <span id="enable-advanced-privacy-postback"></span>Enable Advanced Privacy postback | Setup Advanced Privacy integration to comply with an advertiser's data sharing policy.<br /><br />[More about Advanced Privacy postbacks.](/docs/advanced-privacy-guide-postback-macros-for-ad-networks) | **To enable:**<ol><li>Follow the [instructions for Advanced Privacy postback configuration](/docs/self-serve-integration-management-for-ad-networks) in the AppsFlyer dashboard.</li><li>Make sure [your attribution link has all mandatory parameters](/docs/advanced-privacy-guide-postback-macros-for-ad-networks#click-url-requirements).</li></ol>In case of any issues, or if you must add parameters to your attribution link template:<ol><li>Select **Advanced privacy or SKAD mode** from the widget.</li><li>Write "Enable Advanced Privacy postback" as the ticket title.</li><li>Share the following information:<ul><li>Your PID or login username</li><li>Advanced Privacy postback structure based on available macros</li><li>For the link update: new parameters and their corresponding macros</li></ul></li></ol> |
| <span id="enable-skadnetwork-postback"></span>Enable SKAdNetwork postback | Setup SKAdNetwork integration and the ability to receive decoded data from AppsFlyer via postbacks.<br /><br />[More about SKAdNetwork postbacks.](/docs/skan-integration-guide-for-ad-networks) | **To enable:**<br /><br />Follow the [instructions for SKAdNetwork postback configuration](/docs/self-serve-integration-management-for-ad-networks) in the AppsFlyer dashboard.<br /><br />In case of any issues:<ol><li>Select **Advanced privacy or SKAD mode** from the widget.</li><li>Write "Enable Advanced Privacy postback" as the ticket title.</li><li>Share the following information:<ul><li>Your PID or login username</li><li>SKAdNetwork postback structure based on available macros from KB</li><li>Apple SKAdNetwork ID</li></ul></li></ol> |
| <span id="update-the-logo"></span>Update the logo | Add a logo, or replace the current one. | **To update the logo:**<ol><li>Make sure you have a suitable logo file: (200x50px transparent PNG)</li><li>Log in to the AppsFlyer dashboard.</li><li>Click the email address in the top right corner > Select **Partner setup**.</li><li>Go to **Profile** tab > **Company logo**.</li><li>Click the **Upload** icon.</li><li>Select the logo file and confirm.</li><li>Click **Save** at the bottom of the page. The logo is updated immediately.</li></ol> |
| <span id="update-the-click-attribution-url"></span>Update the click attribution URL | Update click attribution URL that advertisers use for running campaigns with you.  <br />[More about attribution links.](/marketers/docs/about-link-structure-and-parameters) | Follow the instructions in [Self-serve integration management for ad networks](/docs/self-serve-integration-management-for-ad-networks) to configure the attribution URL in the AppsFlyer postback management platform.<br /><br />In case of any issues, or if you can't access the Postback Management Platform:<ol><li>Select Default mode from the widget.</li><li>Write "Update click attribution URL" as the ticket title.</li><li>Share the following information:</li></ol><ul><li>Your PID or login username</li><li>New parameters and their corresponding macros.</li></ul>After the click attribution URL is updated, ask the advertiser for the updated attribution link URL. |
| <span id="disable-integration"></span>Disable integration | If an integration is disabled, installs and in-app events will no longer be attributed to that integration. The integration will also be removed from the Marketplace and become invisible to advertisers. However, your account will remain accessible to the account admin and users, and all previously collected attribution data will still be available.<br /><br />**Note:** Before disabling, verify that advertisers have stopped working with the integration. | **To disable integration:**<ol><li>Select **Default mode** from the widget.</li><li>Write "Disable integration" as the ticket title.</li><li>Share the following information:<ul><li>Your PID or login username</li><li>Which integration to disable: install, in-app events, or both.</li></ul></li></ol> |
| <span id="add-new-dashboard-parameter"></span>Add new dashboard parameter | Allow advertisers to provide a specific parameter in the AppsFlyer advertiser dashboard, so they can be received via a postback. | **To add a new dashboard parameter:**<ol><li>Select **Default mode** from the widget.</li><li>Write "Add new dashboard parameter" as the ticket title.</li><li>Share the following information:<ul><li>Your PID or login username</li><li>The new dashboard parameter name</li><li>The receiving parameter—if you want to receive it via install or in-app event postback</li><li>[Recommended] The description of the parameter that will be displayed in a tooltip next to the parameter field in the AppsFlyer dashboard for advertisers</li></ul></li></ol> |
| <span id="provide-the-postback-template-to-the-partner"></span>Review the postback templates | Review your current install or in-app event postback templates. | Follow the instructions in [Self-serve integration management for ad networks](/docs/self-serve-integration-management-for-ad-networks) to review your postback templates in the AppsFlyer dashboard.<br /><br />In case of you can't access Postback Management Platform:<ol><li>Select Default mode from the widget.</li><li>Use "Provide postback template" as the ticket title.</li><li>Share the following information:</li></ol><ul><li>Your PID or login username</li><li>Specify which postback you want to check: install postback, in-app event postback, or both</li></ul> |
| <span id="implement-click-signing"></span>Implement click signing | Add signature validation to clicks to avoid fraud liabilities and so fraudulent clicks aren't attributed to your ad network. | Follow [these instructions](/docs/click-signing-for-ad-networks) to implement click signing on your side.<br />In case of questions:<ol><li>Select **Default mode** from the widget.</li><li>Write "Click signing" as the ticket title.</li><li>Share your PID or login username.</li></ol> |
| <span id="implement-incost-api"></span>Implement inCost API | Ad network partners can send cost data to AppsFlyer using the inCost API. AppsFlyer ingests and processes the data, and makes it available to advertisers and partners via dashboards and reports. | **To implement inCost API:**<ol><li>Select "**3. I would like to learn more about Appsflyer features&capability"** from the widget.</li><li>Select "**4. Enabling cost measurement"** from the widget.</li><li>Use "inCost API integration" as the ticket title.</li><li>Share the following information:</li></ol><ul><li>Your PID or login username</li></ul> |
| <span id="implement-audience-feature"></span>Implement Audience feature | Audience integration enables you to easily and continuously receive your clients audience segment data so you can serve your tailored campaigns. | **To implement Audience feature:**<ol><li>Select "**3. I would like to learn more about Appsflyer features&capability"** from the widget.</li><li>Select "**1.Audiences"** from the widget.</li><li>Write "Audience integration" as the ticket title.</li><li>Share the following information:</li></ol><ul><li>Your PID or login username</li><li>The advertiser name who referred you for the audience integration</li></ul> |
